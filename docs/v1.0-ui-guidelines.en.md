# OpsPilot V1.0 UI Guidelines

> Language: [简体中文](./v1.0-ui-guidelines.md) | English (current)

These guidelines define the minimum UI bar for V1.0 pages and acceptance reviews.

## 1. Layout And Responsiveness

- Core pages must render on desktop and narrow-width screens without horizontal overflow
- Tables must remain readable through wrapping, truncation, or stacked secondary text
- Filters and action areas must collapse without hiding critical actions
- JSON payload panels, timelines, and audit/event views must stay scroll-safe

## 2. Localization

- User-facing copy must support zh/en
- Technical terms may stay as `Agent`, `Host`, `Webhook`, `Metric`, `SMTP`, `HMAC`, and `JSONPath`
- Default samples, validation messages, action reasons, and empty states must also be localized

## 3. Shared Components

The following shared primitives are the default V1.0 building blocks:

- `DataTable`
- `FilterToolbar`
- `JsonViewer`
- `PaginationBar`
- `Timeline`
- `ConfirmDialog`

## 4. Security Display Rules

- Secrets must never be rendered back after creation or rotation except for one-time issuance moments already defined by the API
- API/audit failure details must stay masked when they may contain tokens, passwords, or signing secrets
- Webhook/Audit/Notification screens must prefer masked summaries over raw secret payloads

## 5. Webhook UI Rules

- Rule editor must expose the full V1.0 matcher set, including `payload_exists`, `payload_not_equals`, `payload_regex`, and array wildcard paths
- Matcher simulator must show per-condition result, actual value, and failure reason
- Event detail must show headers, payload, security state, and linked task/workflow runs

## 6. Acceptance Expectation

If a page introduces new workflow, webhook, audit, notification, or alert behavior, the page must be checked for:

- zh/en copy
- responsive-safe layout
- permission-aware actions
- safe rendering of sensitive data
