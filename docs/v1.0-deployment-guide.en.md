# OpsPilot V1.0 Deployment Guide

> Language: [简体中文](./v1.0-deployment-guide.md) | English (current)

This guide defines the supported V1.0 deployment path for local validation, CI parity, and Docker/Compose release checks.

## 1. Supported Baseline

- OS: Windows PowerShell or Linux shell with Docker support
- Go: `1.26.2`
- Node.js: `24.x`
- npm: `11.x`
- MySQL: `8.0.39`
- Redis: `7.x`
- Docker Compose: profile support required

## 2. Required Secrets And Environment

Backend requires:

- `DATABASE_DSN`
- `REDIS_ADDR`
- `JWT_SECRET`
- `AGENT_SHARED_SECRET`
- `SECRET_ENCRYPTION_KEY`

Recommended production constraints:

- Reject empty `SECRET_ENCRYPTION_KEY`
- Use a dedicated MySQL user instead of `root`
- Restrict `HTTP_ALLOW_ORIGIN`
- Persist MySQL and Redis volumes outside ephemeral containers

## 3. Database Bootstrap

For a clean V1.0 environment, apply the active root migration chain:

```powershell
cd D:\+\1108026_rust_go\OpsPilot
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000001_init_mysql_schema.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000002_seed_initial_auth_data.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000003_task_execution_security.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000004_v07_webhook_security.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000005_v10_productization_bundle.up.sql
```

The archived `server/migrations/archive/v1.0-incremental/` files are kept only for historical comparison and legacy-path validation.

## 4. Local Service Startup

Backend:

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server
Copy-Item .\.env.example .\.env
go run .\cmd\api
```

Frontend:

```powershell
cd D:\+\1108026_rust_go\OpsPilot\web
npm install
npm run dev
```

Agent:

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server
go run .\cmd\agent
```

## 5. Docker/Compose Startup

Infrastructure only:

```powershell
cd D:\+\1108026_rust_go\OpsPilot
docker compose -f .\deploy\docker-compose.yml up -d
```

Full V1.0 stack:

```powershell
cd D:\+\1108026_rust_go\OpsPilot
Copy-Item .\deploy\.env.example .\deploy\.env -ErrorAction SilentlyContinue
docker compose --env-file .\deploy\.env -f .\deploy\docker-compose.yml --profile full up --build
```

Current Compose expectations:

- No fixed container names
- Published ports are overridable from `.env`
- API and Agent run with `TZ=Asia/Shanghai` to keep wait/schedule behavior aligned in Docker

## 6. Pre-Release Validation

Run before tagging or shipping:

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server
go test ./...
go vet ./...
cd ..\web
npm run build
cd ..
powershell -File .\scripts\migration-check.ps1 -SkipExecution
powershell -File .\scripts\openapi-router-check.ps1
```

Docker and full-stack smoke:

```powershell
cd D:\+\1108026_rust_go\OpsPilot
docker compose -f .\deploy\docker-compose.yml --profile full config
powershell -File .\scripts\e2e-smoke.ps1 -ApiBaseUrl http://127.0.0.1:8080 -ScheduleTimeoutSeconds 180
```

## 7. V1.0 Operational Guarantees

- Manual, schedule, and webhook workflow triggers are expected to work
- Workflow runs and node runs must remain traceable, cancelable, and retryable
- Notification channel secrets must stay encrypted at rest and masked in API, logs, and audit trails
- Audit export and retention must produce auditable records
- OpenAPI must stay in sync with router-exposed endpoints
