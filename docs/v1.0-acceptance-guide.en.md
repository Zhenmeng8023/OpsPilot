# OpsPilot V1.0 Acceptance Guide

> Language: [简体中文](./v1.0-acceptance-guide.md) | English (current)

This guide is the execution checklist for the V1.0 acceptance gates defined in Section 13.1 and Section 16 of the V1.0 design document.

## 1. Mandatory Commands

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server
go test ./...
go vet ./...
cd ..\web
npm run build
cd ..
powershell -File .\scripts\migration-check.ps1 -SkipExecution
powershell -File .\scripts\openapi-router-check.ps1
docker compose -f .\deploy\docker-compose.yml --profile full config
powershell -File .\scripts\e2e-smoke.ps1 -ApiBaseUrl http://127.0.0.1:8080 -ScheduleTimeoutSeconds 180
```

## 2. Acceptance Gates

| Gate | Evidence |
| --- | --- |
| CI is green | GitHub Actions push run completes successfully |
| Go backend quality | `go test ./...` and `go vet ./...` pass |
| Frontend buildability | `npm run build` passes |
| Migration quality | Pair check passes; empty database path is valid |
| Docker release path | Compose config and image builds succeed |
| Workflow triggers | Manual, schedule, and webhook flows pass smoke |
| Workflow operations | Run cancel, whole-run retry, and node retry pass smoke |
| Secret governance | Notification channel config is masked in API/audit and encrypted at rest |
| Audit governance | Export and retention endpoints succeed and leave audit records |
| API contract | OpenAPI/router diff check passes |
| UI baseline | Key pages build with zh/en copy and responsive-safe layouts |

## 3. Webhook Matcher Completion Criteria

The V1.0 webhook matcher is complete only when all of the following are true:

- `header_equals`
- `payload_equals`
- `payload_contains`
- `payload_not_equals`
- `payload_exists`
- `payload_regex`
- `event_type_equals`
- `ref_equals`
- `branch_equals`
- JSONPath array wildcard paths such as `commits[*].author.name`
- Matcher simulator returns per-condition results
- Historical event replay remains available

## 4. Documentation Completion Criteria

The V1.0 documentation set is complete only when the repository contains:

- Product development design
- Release evidence / release notes
- Deployment guide
- Acceptance guide
- UI guidelines

## 5. Exit Rule

V1.0 is accepted only when every gate above passes and repository-level docs stay aligned with the current code and CI behavior.
