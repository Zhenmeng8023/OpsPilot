本文档是 V1.0 设计书第 13.1 节和第 16 节的执行型验收清单。

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server

cd ..\web
npm run build
cd ..
powershell -File .\scripts\migration-check.ps1 -SkipExecution

```

## 2. 验收门槛

| 门槛 | 证据 |
| --- | --- |
| CI 为绿 | GitHub Actions push run 成功 |
| Go 后端质量 | `go test ./...`、`go vet ./...` 通过 |
| 前端可构建 | `npm run build` 通过 |
| 迁移质量 | pair check 通过，空库路径有效 |
| Docker 发布路径 | Compose config 和镜像构建通过 |
| Workflow 触发 | Manual / Schedule / Webhook smoke 全通过 |
| Workflow 运维能力 | run cancel、整 run retry、node retry 通过 |
| Secret 治理 | notification channel config 在 API/audit 中脱敏，落盘加密 |
| Audit 治理 | export / retention 成功且留下审计记录 |
| API 契约 | OpenAPI/router diff 检查通过 |
| UI 基线 | 关键页面以 zh/en 文案构建通过，并保持响应式安全布局 |

## 3. Webhook Matcher 完成标准

V1.0 的 webhook matcher 只有在下面全部成立时才算完成：

- `header_equals`
- `payload_equals`
- `payload_contains`
- `payload_not_equals`
- `payload_exists`
- `payload_regex`
- `event_type_equals`
- `ref_equals`
- `branch_equals`
- 支持 `commits[*].author.name` 这类 JSONPath 数组通配
- matcher simulator 返回逐条件结果
- historical event replay 可用

## 4. 文档完成标准

只有仓库同时具备以下文档，V1.0 文档套件才算完整：

- 产品开发设计书
- 发布记录 / release notes
- 部署手册
- 验收手册
- UI 规范

## 5. 退出规则

只有当以上所有门槛都通过，且仓库文档与当前代码、CI 行为保持一致时，V1.0 才能算验收完成。
