# OpsPilot V1.0 部署手册

> Language: 简体中文（当前） | [English](./v1.0-deployment-guide.en.md)

本文档定义 V1.0 的标准部署路径，用于本地验收、CI 对齐和 Docker/Compose 发布验证。

## 1. 支持基线

- 操作系统：Windows PowerShell 或支持 Docker 的 Linux shell
- Go：`1.26.2`
- Node.js：`24.x`
- npm：`11.x`
- MySQL：`8.0.39`
- Redis：`7.x`
- Docker Compose：需要支持 profile

## 2. 必需环境变量与密钥

后端至少需要：

- `DATABASE_DSN`
- `REDIS_ADDR`
- `JWT_SECRET`
- `AGENT_SHARED_SECRET`
- `SECRET_ENCRYPTION_KEY`

生产环境建议：

- 禁止 `SECRET_ENCRYPTION_KEY` 为空
- 使用专用 MySQL 账号而不是 `root`
- 收紧 `HTTP_ALLOW_ORIGIN`
- 将 MySQL/Redis 数据卷放在持久化存储上

## 3. 数据库初始化

空库按当前 V1.0 根迁移链执行：

```powershell
cd D:\+\1108026_rust_go\OpsPilot
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000001_init_mysql_schema.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000002_seed_initial_auth_data.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000003_task_execution_security.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000004_v07_webhook_security.up.sql
mysql -h 127.0.0.1 -P 3306 -uopspilot -popspilot opspilot < .\server\migrations\000005_v10_productization_bundle.up.sql
```

`server/migrations/archive/v1.0-incremental/` 中的历史增量文件仅用于历史对照和旧链路校验，不再作为新环境启动路径。

## 4. 本地服务启动

后端：

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server
Copy-Item .\.env.example .\.env
go run .\cmd\api
```

前端：

```powershell
cd D:\+\1108026_rust_go\OpsPilot\web
npm install
npm run dev
```

Agent：

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server
go run .\cmd\agent
```

## 5. Docker / Compose 启动

仅启动基础设施：

```powershell
cd D:\+\1108026_rust_go\OpsPilot
docker compose -f .\deploy\docker-compose.yml up -d
```

启动完整 V1.0 栈：

```powershell
cd D:\+\1108026_rust_go\OpsPilot
Copy-Item .\deploy\.env.example .\deploy\.env -ErrorAction SilentlyContinue
docker compose --env-file .\deploy\.env -f .\deploy\docker-compose.yml --profile full up --build
```

当前 Compose 约束：

- 不使用固定 `container_name`
- 发布端口可通过 `.env` 覆盖
- API 和 Agent 注入 `TZ=Asia/Shanghai`，避免 Docker 环境下 wait/schedule 漂移

## 6. 发布前验证

发布前至少运行：

```powershell
cd D:\+\1108026_rust_go\OpsPilot\server
go test ./...
go vet ./...
cd ..\web
npm run build
cd ..
powershell -File .\scripts\migration-check.ps1 -SkipExecution
powershell -File .\scripts\openapi-router-check.ps1
```

Docker 与全栈 smoke：

```powershell
cd D:\+\1108026_rust_go\OpsPilot
docker compose -f .\deploy\docker-compose.yml --profile full config
powershell -File .\scripts\e2e-smoke.ps1 -ApiBaseUrl http://127.0.0.1:8080 -ScheduleTimeoutSeconds 180
```

## 7. V1.0 运行保证

- Manual / Schedule / Webhook workflow 触发必须可用
- Workflow run 和 node run 必须可追踪、可取消、可重试
- Notification channel secret 必须落盘加密，且不能通过 API、日志、审计泄露
- Audit export / retention 必须可用且产生审计记录
- OpenAPI 必须与 router 暴露的接口保持一致
