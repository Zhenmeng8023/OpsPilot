# OpsPilot V0.7 Release Notes

> Language: [简体中文](./v0.7-release-notes.md) | English (current)

Generated on 2026-05-08.

## Positioning

V0.7 is a stabilization release. The goal is not to add another large product area, but to make the existing T1-T8 capabilities reliable enough for CI, demo, deployment, and production-like validation.

Current version marker: `0.7.0-dev`.

## Completed In This Release Cycle

### Release Engineering

- GitHub Actions CI covers backend tests, `go vet`, migration pair checks, frontend build, and Docker build.
- `VERSION` and `/api/v1/version` expose build identity.
- API/Web Dockerfiles and the Compose `full` profile support full-stack startup.
- OpenAPI has been updated for the V0.7 core API surface.
- E2E demo, security permission matrix, security checklist, and changelog are now tracked as release artifacts.

### Security Baseline

- Production public registration is disabled by default.
- Production JWT secrets are validated.
- CORS uses explicit allowlist behavior.
- User JWT, Agent token, and Webhook token boundaries are tested.
- Webhook trigger token and signing secret are split.
- Logs and audit payloads redact token/password/secret/authorization values.

### Webhooks

- Timestamp, nonce, and delivery-id replay protection are implemented.
- Failed trigger attempts are persisted with failure reasons.
- Rule matchers support AND conditions across headers, event types, JSON fields, refs, and branches.
- Webhook event queries support source, status, deliveryId, and received time range filters.
- Source/rule lifecycle actions and event debugging are available in the UI.

### Schedules

- Cron next preview can show upcoming fire times before a schedule is created.
- Misfire policy is wired into creation and scanner behavior with `skip`, `fire_once`, and `fire_all`.
- Trigger history API/UI shows recent trigger records, task runs, and failure reasons.
- Cron parser tests cover step, range, list, Sunday, invalid expressions, and timezone behavior.

### Metrics And Alerts

- Agent uploads real OS metrics for CPU, memory, disk, and network.
- Metrics trend API and frontend trend charts are available.
- Alerts support ack, silence, unsilence, resolve, cooldown, recovery notifications, history, and event details.
- Alert duration windows now require sustained threshold violations.

### Notifications

- SMTP Email sending is implemented through environment variables.
- Delivery listing, manual retry, and channel test send are implemented.
- Channel list responses are masked through `targetSummary`.
- Outbound webhook notifications are signed with `X-OpsPilot-*` headers.

### Frontend Experience

- Metrics, Alerts, and Notifications pages now have more complete states, filters, and operations.
- The Audit Logs page is wired to `audit.read` and can search audit events plus inspect redacted before/after/metadata.
- UI language switching continues to be supported through the existing i18n layer; product and technical terms such as Agent, Host, Webhook, Metric, SMTP, and HMAC remain untranslated.
- Visual styling continues to converge on one operations-console theme.

## Required Validation Before Tagging

Run:

```powershell
cd server
go test ./...
go vet ./...

cd ..\web
npm run build

cd ..
powershell -File .\scripts\migration-check.ps1 -SkipExecution
```

When Docker is available, also run:

```powershell
docker compose -f deploy/docker-compose.yml --profile full config
docker build -f server/Dockerfile .
docker build -f web/Dockerfile .
```

## Known Gaps

- Notification channel config is masked at API/log/audit boundaries but is not encrypted at rest.
- Docker image build validation still needs to be run in an environment with Docker available.

## Suggested Next Implementation Order

1. Add Docker validation to a machine with Docker available and record the result.
2. Improve Audit Logs with export, retention policy, and advanced search.
3. Add encrypted storage for notification channel config.
4. If validation stays green, prepare `v0.7.0` tag from a clean release branch.
